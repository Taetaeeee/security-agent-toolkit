## **오늘 한 것**
Flask로 POST 요청을 받는 웹훅 서버를 만들었다.

`curl`로 JSON 데이터를 보내고 응답 상태코드를 확인했다.

받은 경보를 `received_alerts.json`에 저장하고, `.sh` 파일로 여러 요청을 한 번에 테스트했다.

오후에는 `brute_force`, `password_spraying`, `night_login` 룰을 만들고, 같은 경보가 중복 전송되지 않도록 `processed_ids.json`을 사용했다.

`schedule`을 이용해 일정한 간격으로 작업을 자동 실행했다.

## **찾아보고 알게 된 것**
웹훅은 일이 발생했을 때 정해진 주소로 요청을 보내는 방식이다.

`request.get_json()`으로 POST 요청의 JSON 데이터를 딕셔너리로 받을 수 있다.

HTTP 상태코드로 오류 원인을 구분할 수 있다.

- `200` : 정상
- `404` : 주소 없음
- `405` : 허용되지 않은 요청 방식
- `415` : 요청 데이터 형식 문제

딕셔너리에 키가 있는지 확인할 때는 `event["user"]`가 아니라 `"user" in event`를 사용할 수 있다.

같은 경보를 반복해서 보내지 않으려면 사건마다 고유한 `id`를 만들고 이미 처리한 `id`를 저장해둘 수 있다.

`schedule`은 파이썬 프로그램이 실행 중일 때 정해진 간격으로 작업을 실행한다.

## **막힌 것**
`status`를 `statue`로 잘못 입력했다.

`received_alerts.json` 파일 이름의 철자를 잘못 입력했다.

서버를 여러 번 실행해 같은 포트에 프로세스가 남아 있었고, `netstat`으로 포트 상태를 확인했다.

`if event["user"]:`를 사용해 `user` 키가 없는 이벤트에서 `KeyError`가 발생했다.

`night_login`에서 로그의 시간이 아니라 `time` 모듈을 사용해 잘못된 경보 ID가 만들어졌다.

Git push 과정에서 원격 저장소와 로컬 커밋 상태가 달라 `rebase` 후 다시 push했다.
