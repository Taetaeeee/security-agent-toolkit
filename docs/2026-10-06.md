## **찾아보고 알게 된 것**
API 키는 사용자를 확인하고 접근 권한과 사용량을 관리하기 위한 인증 수단이다.

`response`는 응답 객체이므로 상태코드를 확인할 때는 `response.status_code == 200`처럼 비교해야 한다.

API 응답은 `response.json()`으로 딕셔너리 형태로 바꿀 수 있다.

`system`은 모델의 역할이나 답변 방식을 지시하고, `user`에는 실제 질문을 넣는다.

API 요청 본문에서는 `message`가 아니라 `messages`를 사용한다.

LLM이 JSON으로 답해도 처음에는 문자열이므로 `json.loads()`를 사용해 딕셔너리로 변환할 수 있다.

문자열을 쉼표로 나열하면 하나의 문자열이 아니라 `tuple`이 만들어진다.

딕셔너리에는 함수도 값으로 저장할 수 있고, `tool_registry["키"] = 함수` 형태로 기존 딕셔너리에 추가할 수 있다.

## **키가 틀렸을 때와 키가 없을 때의 차이**
잘못된 키를 보내면 `UNAUTHENTICATED`가 나오고, 키를 아예 보내지 않으면 `PERMISSION_DENIED`가 나온다.

`response == 200`은 응답 객체와 숫자를 비교하는 것이므로 올바른 방법이 아니다.

상태코드는 `response.status_code == 200`으로 확인해야 한다.

## **막힌 것**
`response == 200`으로 작성해 상태코드를 잘못 비교했다.

`question = instruction, example, "로그: " + log`처럼 작성해 문자열이 아닌 튜플이 만들어졌다.

API 요청 본문의 키를 `message`로 작성했는데 실제로는 `messages`여야 했다.

`system`과 `user`에 어떤 내용을 넣어야 하는지 처음에는 헷갈렸다.

`tool_registry`에 함수를 추가하는 것과 딕셔너리를 새로 만드는 것의 차이가 헷갈렸다.
