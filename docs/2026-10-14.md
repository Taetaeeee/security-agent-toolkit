# 2026-10-14 (수)

## 찾아본 것

서버에서 로그 파일을 옮기고 백업할 때 `cp`, `mv`, `scp`, `tar` 같은 명령어를 사용할 수 있다.

- `cp` : 원본 파일을 유지하면서 복사본을 만들어 백업
- `mv` : 파일을 다른 폴더로 이동하거나 이름 변경
- `scp` : SSH를 이용해 다른 서버로 파일을 안전하게 복사
- `tar` : 여러 로그 파일을 하나로 묶어 압축해서 보관

서버에서는 마우스나 VS Code 같은 화면 환경이 없는 경우가 많기 때문에 터미널 명령어를 이용해 파일을 만들고, 복사하고, 이동하고, 삭제한다.

`touch`는 빈 파일을 만들 수 있고, 같은 이름의 파일이 이미 있으면 내용은 그대로 두고 수정 시각만 바뀐다.
`cp`와 `mv`는 같은 이름의 파일이 있으면 기본적으로 묻지 않고 덮어쓸 수 있기 때문에 로그 파일을 다룰 때는 덮어쓰기 여부를 확인하는 옵션을 사용하는 것이 안전하다.
`rm`은 휴지통으로 보내는 것이 아니라 바로 삭제하기 때문에 실행하기 전에 `pwd`와 `ls`로 현재 위치와 삭제할 파일을 확인하는 것이 중요하다.

DNS는 `naver.com` 같은 도메인 이름을 IP 주소로 바꿔 주는 역할을 한다.
`nslookup`을 사용하면 DNS 서버에 직접 도메인 이름의 IP 주소나 NS, MX, CNAME 같은 레코드를 물어볼 수 있다.
DNS에서 `NXDOMAIN`은 존재하지 않는 도메인이라는 뜻이다.
DNS의 TTL은 DNS 응답을 캐시에 몇 초 동안 저장할지를 나타내며, `ping`에서 봤던 TTL과는 의미가 다르다.
악성코드는 DGA를 이용해 무작위로 보이는 도메인을 여러 개 만들 수 있고, 감염된 PC에서 `NXDOMAIN`이 반복적으로 발생하면 의심할 수 있다.
정상인데 의심으로 판단한 것은 오탐, 실제 의심인데 정상으로 판단한 것은 미탐이라고 한다.

## 오늘 새로 쓴 명령

`touch`, `cp`, `mv`, `rm`, Tab 자동 완성, `nslookup`
`touch memo.txt`로 빈 파일을 만들었다.
`cp a.log b.log`로 `a.log`를 복사해 `b.log`를 만들었다.
`mv b.log c.log`로 파일 이름을 변경했다.
`mv c.log ./backup/`으로 파일을 `backup` 폴더 안으로 이동했다.
`rm memo.txt`로 파일을 삭제했다.

Tab 키를 사용하면 파일이나 폴더 이름을 끝까지 직접 입력하지 않아도 자동 완성할 수 있다.

`nslookup example.com`으로 도메인 이름의 IP 주소를 확인했다.
`ipconfig //displaydns`로 내 PC의 DNS 캐시를 확인하고, `ipconfig //flushdns`로 DNS 캐시를 비울 수 있다.

## 찾은 옵션

폴더째 복사 - `-r`
```bash
cp -r backup backup2
```

덮어쓰기 전에 묻기 - `-i`
```bash
cp -i a.log ./backup/
```
같은 이름의 파일이 있으면 다음과 같이 덮어쓸지 물어본다.
```text
cp: overwrite './backup/a.log'?
```

폴더째 지우기 - `-r`
```bash
rm -r ./backup2
```

## mv 의 두 가지 쓰임

이름 바꾸기:
```bash
mv b.log c.log
```
`b.log`의 이름이 `c.log`로 바뀐다.

옮기기:
```bash
mv c.log ./backup/
```
`c.log`가 `backup` 폴더 안으로 이동한다.

`mv`는 뒤에 적은 값이 새로운 파일 이름이면 이름을 바꾸고, 폴더이면 그 폴더 안으로 파일을 이동한다.

## 막힌 것

현재 위치를 확인하려고 `pwd`를 입력해야 하는데 `pwed`라고 입력해서 `command not found`가 발생했다.
```text
bash: pwed: command not found
```

`backup` 폴더로 파일을 옮길 때
```bash
mv c.log /backup
```
이라고 입력했더니 `Permission denied`가 발생했다.
`/backup`은 현재 폴더 안의 `backup`이 아니라 루트(`/`) 아래의 `backup`을 의미했다.

현재 폴더 안에 만든 `backup`을 사용하려면
```bash
mv c.log ./backup/
```
처럼 작성해야 했다.

`cp -i`에서도 처음에
```bash
cp -i a.log /backup
```
이라고 작성해서 같은 문제가 발생했고,
```bash
cp -i a.log ./backup/
```
으로 수정해서 정상적으로 복사했다.
