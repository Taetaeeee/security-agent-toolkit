# 2026-10-16 (금)

## 찾아본 것

서버에서 설정 파일을 수정할 때 터미널에서 사용하는 편집기인 `vim`을 사용할 수 있다는 것을 확인했다.

`vim`은 일반 모드, 입력 모드, 명령줄 모드로 나뉘어 있고 현재 어떤 모드인지에 따라 같은 키의 동작이 달라졌다.

- 일반 모드: 이동, 삭제, 복사 같은 명령을 사용했다.
- 입력 모드: 글자를 입력했다.
- 명령줄 모드: 저장, 종료, 바꾸기 같은 명령을 사용했다.

일반 모드에서 `i`를 누르면 입력 모드로 들어갔고, `Esc`를 누르면 다시 일반 모드로 돌아왔다.

파일을 수정한 뒤에는 `:wq`로 저장하고 나갈 수 있었고, 잘못 수정했을 때는 `:q!`로 저장하지 않고 나갈 수 있었다.

`dd`로 한 줄을 지우고 `u`로 되돌릴 수 있었으며, `yy`로 한 줄을 복사하고 `p`로 붙여 넣을 수 있었다.

`/WARN`처럼 `/단어`를 사용해 파일 안에서 원하는 내용을 찾을 수 있었고, `:%s/WARN/ERROR/g`를 사용해 파일 전체의 같은 단어를 한 번에 바꿀 수 있었다.

`touch`는 파일을 바로 만들지만, 존재하지 않는 파일을 `vim`으로 열기만 하고 저장하지 않으면 실제 파일은 만들어지지 않는 것도 확인했다.

## 오늘 새로 쓴 명령

`vim`

```bash
vim notes.txt
```

`vim`으로 파일을 열거나 새로운 파일을 작성했다.

## vim 으로 한 것

입력 모드로 들어가는 키: i

일반 모드로 돌아오는 키:Esc

저장하고 나가는 명령: :wq

저장 없이 나가는 명령: :q!

지운 것을 되돌리는 키:u

추가로 사용한 명령:
| 키 · 명령 | 하는 일 |
|---|---|
| `dd` | 현재 줄을 지웠다 |
| `yy` | 현재 줄을 복사했다 |
| `p` | 복사한 줄을 붙여 넣었다 |
| `/WARN` | 파일에서 `WARN`을 찾았다 |
| `n` | 다음 검색 결과로 이동했다 |
| `gg` | 파일 맨 위로 이동했다 |
| `G` | 파일 맨 아래로 이동했다 |
| `:%s/WARN/ERROR/g` | 파일 전체의 `WARN`을 `ERROR`로 바꿨다 |

## 막힌 것

입력 모드와 일반 모드를 구분해야 하는 점이 처음에는 헷갈렸다.

입력 모드에서 `:wq`를 입력하면 저장 명령이 아니라 그대로 글자로 입력되기 때문에 먼저 `Esc`를 눌러 일반 모드로 돌아와야 했다.

파일을 수정하고 저장하지 않은 상태에서 `:q`로 나가려고 하면 다음과 같은 오류가 발생했다.

```text
E37: No write since last change (add ! to override)
```

수정한 내용을 버리고 나가려면 `:q!`를 사용해야 했다.

`dd`로 줄을 잘못 지웠을 때는 `u`를 눌러 바로 되돌릴 수 있다는 것도 확인했다.
