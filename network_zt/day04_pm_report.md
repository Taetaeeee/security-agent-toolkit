## 5교시 · 규칙 읽기 · 로그

### 문제 5-1 · 5교시 규칙표로 요청 세 개를 손으로 판정하기

- (가) 세 요청마다 처음 맞은 규칙 번호와 허용 / 차단을 적어 주세요.
  - 쓸 내용: 「A 규칙 ○ · 허용 또는 차단」처럼 세 줄
  - 답: A	규칙 3 허용
        B	규칙 5 차단
        C 규칙 5 차단
- (나-1) 🔍 A 와 B 는 같은 부산 지점이 같은 포트로 가는데 결과가 다릅니다. 무엇이 달라서일까요?
  - 쓸 내용: ① 두 요청에서 달라진 값 하나 ② 그 값 때문에 각각 몇 번 규칙에 맞았는지
  - 답: A와 B는 출발지가 부산 지점이고 포트도 443으로 같지만 목적지가 다르다.
        A는 업무 포털로 접속하므로 규칙 3번에 일치하여 허용된다. 반면 B는 웹메일로 접속하지만 부산 지점에서 웹메일로 가는 허용 규칙이 없기 때문에 규칙 5번에 일치하여 차단된다. A > 업무 포털 > 규칙 3, B > 웹 메일 > 규칙 5
- (나-2) 🔍 5번 줄을 맨 위(1번 자리)로 올리면 A ~ C 는 각각 어떻게 될까요? 그래서 `any` 규칙은 어디에 둬야 할까요?
  - 쓸 내용: ① A ~ C 의 새 결과 ② `any` 규칙을 둘 위치와 이유
  - 답: A	규칙 5 차단
        B	규칙 5 차단
        C 규칙 5 차단

        any는 어떤 출발지, 목적지, 포트에도 일치하므로 any / any / any / 차단 규칙은 허용 규칙을 먼저 검사할 수 있도록 맨 마지막에 두어야 한다.

  - 쓸 내용: ① SYN 횟수 ② 줄마다의 `Time` 값 ③ 상대에게서 온 것 ④ `curl` 마지막 문구 한 줄

- (나-1) 🔍 81번 연결은 3-way handshake 의 어디에서 멈췄나요? 5.2 의 두 방식 가운데 어느 쪽이고, 그렇게 판단한 근거 화면은 무엇인가요?
  - 쓸 내용: ① 멈춘 단계(SYN · SYN/ACK · ACK 가운데) ② 드롭 / 거부 가운데 하나와 근거 화면

  - 쓸 내용: ① (가-2) 의 `Time` 값으로 구한 줄 사이 간격 두 가지(앞부분 · 뒷부분, 예: 1.0초, 2.0초) ② 간격이 일정했는지, 늘어났는지
  - 답: 1.0012782초 -> 2.0002077초 -> 4.0009256초 -> 8.0000922초
        간격이 점점 늘어난다.
- (다) 아래 방화벽 로그의 14:05 네 줄을 `10.8.0.21` PC 쪽에서 패킷으로 보면 어떤 모습일까요? 무엇을 하려던 기록으로 보이는지, 다음에 어떤 기록을 확인하면 좋을지도 적어 주세요.
  - 쓸 내용: ① 패킷으로 보이는 모습(무엇을 보내고 무엇이 안 왔는지) ② 목적지 · 포트 · 간격으로 본 행동 ③ 다음에 확인할 기록
  - 답: 출발지 10.8.0.21에서 관리 서버 10.10.20.9의 22번(SSH)과 443번(HTTPS), 고객 DB 10.10.30.7의 3306번(MySQL), 다른 DB 서버 10.10.30.8의 5432번(PostgreSQL)으로 1초 간격으로 접속을 시도했다. 방화벽이 드롭 방식으로 차단했다면 PC에서는 SYN을 전송했지만 응답을 받지 못하고 재전송하는 모습이 나타날 수 있다. 서로 다른 서버와 포트에 짧은 간격으로 접속을 시도한 점에서 포트 스캔 가능성을 의심할 수 있다.
  다음으로 VPN 게이트웨이 접속 로그를 확인하여 10.8.0.21을 할당받은 사용자 계정과 접속 시간, 원래 출발 공인 IP를 확인하고 정상적인 관리 작업이었는지 조사해야 한다.
- (라) (선택) 사용자가 「회사 서버에 접속이 안 된다」고 합니다. 패킷만 보고 방화벽 문제인지 서버 문제인지 어떻게 나눌 수 있을까요?
  - 쓸 내용: 응답이 아예 없을 때 · RST 가 올 때 · SYN/ACK 가 올 때 각각 무엇을 의심하고 먼저 어디를 볼지. 선택 문항이라 안 쓰면 「선택 안 함」이라고 적습니다
  - 답: SYN을 보냈는데 응답이 전혀 없다면 방화벽에서 패킷을 드롭했거나 네트워크 경로 또는 서버에 문제가 있을 수 있으므로 방화벽 로그와 네트워크 경로를 먼저 확인한다.

  RST가 돌아오면 연결이 거부되었거나 서버의 해당 포트가 닫혀 있을 수 있으므로 서버에서 프로그램이 실행 중인지와 포트 설정을 확인한다.

  SYN/ACK가 돌아오면 TCP 연결 요청에 대한 응답이 있으므로 이후 ACK와 애플리케이션 통신이 정상적으로 이루어지는지 확인한다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요. (「이 교시에 새로 안 것」 칸)
  - 쓸 내용: 새로 안 것 하나와, 그게 왜 기억에 남는지
  - 답: Wireshark에서 TCP 연결이 정상적으로 이루어지는 경우와 차단되는 경우의 패킷 흐름이 다르다는 것을 새로 알게 되었다. 특히 SYN을 보냈지만 SYN/ACK 응답이 없으면 연결 요청을 재전송하고, 재전송 간격도 점점 늘어난다는 점이 기억에 남았다. 또한 서로 다른 서버와 포트에 짧은 간격으로 접속을 시도하는 기록은 포트 스캔을 의심할 수 있으며, 실제 공격인지 판단하려면 방화벽 로그와 VPN 접속 로그를 함께 확인해야 한다는 것을 알게 되었다.

- (다-2) 6번 필터(`tcp.flags.syn == 1 && tcp.flags.ack == 0`)로 바꾸니 2번 필터 화면에서 어떤 패킷이 사라졌나요? 한 PC 가 여러 포트로 연결을 시작한 것을 찾을 때 이 필터를 쓰는 이유는 무엇일까요?
  - 쓸 내용: ① 사라진 패킷의 종류 ② 시작 SYN 만 모아 볼 때 알 수 있는 것
  - 답: 6번 필터로 변경하니 서버가 보낸 SYN/ACK와 RST 응답 패킷이 사라지고, PC가 전송한 SYN과 재전송 SYN만 남았다. 다만 이 필터에는 포트 번호 조건이 없으므로 다른 포트로 보낸 SYN까지 표시되어 기존 화면보다 패킷 수가 많아질 수 있다.

  연결을 시작하는 SYN만 모아 보면 한 PC가 어떤 목적지와 포트로 연결을 시도했는지 쉽게 확인할 수 있다. 따라서 짧은 시간에 여러 포트로 연결을 시도하는 포트 스캔과 같은 의심스러운 행동을 분석할 때 유용하다.

### 문제 6-2 · 허용했는데 왜 막힐까 — 규칙 순서 고치기

- (가-1) 처음 규칙표로 판정한 세 요청의 처음 맞은 규칙 번호와 허용 · 차단을 적어 주세요.
  - 쓸 내용: 「A 규칙 ○ · 허용 또는 차단」처럼 세 줄
  - 답:  A 규칙 1 차단
         B 규칙 1 차단
         C 규칙 1 차단
- (가-2) 2번과 3번을 위로 올린 규칙표로 판정한 세 요청의 처음 맞은 규칙 번호(올린 뒤의 번호)와 허용 · 차단을 적어 주세요.
  - 쓸 내용: 「A 규칙 ○ · 허용 또는 차단」처럼 세 줄
  - 답:  A 규칙 1 허용
         B 규칙 2 허용
         C 규칙 3 차단
- (나) 🔍 처음 규칙표에서 업무 포털 허용 규칙(2번)이 있는데도 왜 막혔을까요?
  - 쓸 내용: ① 처음 규칙표 1번의 목적지 범위와 포트 ② 업무 포털 주소가 그 범위에 들어 있는지 ③ 그래서 2번까지 가지 못한 이유
  - 답: 처음 규칙표의 1번은 VPN 직원이 본사 전체 주소인 `10.10.0.0/16`으로 접속하는 모든 포트를 차단하는 규칙이다. 업무 포털 주소인 `10.10.20.5`도 해당 범위에 포함되고 포트 443도 `any`에 해당한다. 따라서 요청이 1번 차단 규칙에 먼저 일치하여 2번 허용 규칙까지 내려가지 못했기 때문에 업무 포털 접속이 차단되었다.
- (다) 반대로 「부산 지점(`192.168.20.0/24`) → 본사 전체(`10.10.0.0/16`) · `any` · 허용」 규칙이 「부산 지점 → 고객 DB(`10.10.30.7/32`) · `3306` · 차단」 규칙보다 위에 있으면, 부산 지점에서 고객 DB 로 가는 요청은 어떻게 될까요? 어떤 사고가 날까요?
  - 쓸 내용: ① 그 요청이 먼저 맞는 규칙 ② 그래서 생기는 사고
  - 답: 부산 지점에서 고객 DB `10.10.30.7:3306`으로 접속하면 본사 전체 `10.10.0.0/16`과 모든 포트를 허용하는 넓은 규칙에 먼저 일치하여 접속이 허용된다. 따라서 아래에 있는 고객 DB 차단 규칙은 적용되지 않는다. 이 경우 부산 지점에서 고객 DB로 불필요한 접근이 가능해지고, 추가 인증까지 통과하면 고객 정보가 유출되는 등의 보안 사고가 발생할 수 있다.

  - 답: 방화벽은 규칙을 위에서부터 확인하고 처음 일치하는 규칙에 따라 허용하거나 차단한다는 것을 새로 알게 되었다. 특히 업무 포털을 허용하는 규칙이 있더라도 그 위에 본사 전체를 차단하는 규칙이 있으면 접속이 차단된다는 점이 기억에 남았다. 반대로 넓은 허용 규칙이 위에 있으면 차단해야 할 고객 DB까지 접근이 허용될 수 있으므로, 방화벽 규칙은 조건뿐만 아니라 적용 순서도 중요하다는 것을 알게 되었다.

  - 답: 출발지와 목적지, 포트가 구체적으로 지정된 좁은 허용 규칙을 위에 배치하고, 모든 통신을 차단하는 넓은 규칙을 맨 아래에 배치했다.

  7-2에서 추가한 관리자 VPN 허용 규칙은 7번에 넣고 기존 전체 차단 규칙을 8번으로 내렸다. 전체 차단 규칙이 먼저 적용되면 관리자도 관리 서버에 접속할 수 없기 때문이다. 따라서 필요한 통신을 먼저 허용하고 나머지는 차단하도록 순서를 정했다.
- 고객 DB 가 불필요하게 노출되지 않도록 어떻게 했나요?
  - 쓸 내용: ① DB 로 가는 허용 규칙 번호와 출발지 ② 그 밖의 출발지가 맞는 규칙
  - 답: 고객 DB 10.10.30.7의 3306번 포트로 가는 통신은 5번 규칙에서 업무 포털 서버 10.10.20.5/32에만 허용했다.

  VPN 직원, 부산 지점, 외부 인터넷 등 다른 출발지에서 고객 DB로 직접 접속하는 요청은 별도의 허용 규칙이 없으므로 마지막 8번 전체 차단 규칙에 따라 차단된다. 이를 통해 업무상 필요한 서버만 고객 DB에 접근하도록 제한했다.

### 3. 규칙표의 한계 — 문제 7-2 · 오전 4-2

- 이 규칙표를 지켜도 막지 못하는 경우를 하나 적고, 무엇이 더 필요한지 적어 주세요.
  - 쓸 내용: ① 막지 못하는 상황 하나(예: 계정을 빼앗긴 VPN 직원) ② 방화벽이 그것을 못 막는 이유(방화벽이 보는 것) ③ 더 필요한 확인 하나
  - 답: 관리자의 VPN 계정 비밀번호가 탈취되면 공격자가 관리자 계정으로 VPN에 로그인하여 10.8.0.50을 할당받을 수 있다.

  방화벽은 출발지 IP, 목적지 IP, 포트 번호를 확인하지만 실제 접속자가 정상 관리자인지 공격자인지 구분하지 못한다. 따라서 공격자의 통신도 7번 허용 규칙에 일치하여 관리 서버 SSH 접속이 허용될 수 있다.

  이를 방지하기 위해 VPN 로그인 시 비밀번호 외에 다중 인증(MFA)을 적용하고, 로그인 이후에도 사용자 권한과 접속 기록을 추가로 확인해야 한다.

### 4. 오늘 하루 정리

- VPN 과 방화벽은 각각 무엇을 확인하나요? 한 줄씩 비교해 적어 주세요.
  - 쓸 내용: 「VPN: … 를 확인한다 / 방화벽: … 를 확인한다」 두 줄, 각각 언제 확인하는지도 함께
  - 답: VPN: 사용자가 회사 내부망에 접속할 때 계정과 비밀번호 등으로 사용자 인증을 수행하고, 인증에 성공하면 VPN 주소를 할당한다.

  방화벽: VPN 접속 이후 내부 서버로 통신을 시도할 때 출발지 IP, 목적지 IP, 포트를 규칙표와 비교하여 허용하거나 차단한다.
