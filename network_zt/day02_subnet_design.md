## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:
  192 11000000
  168 10101000
  100 01100100
  68  01000100
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답:   192 11000000
          앞자리를 0으로(0) 채운 8자리(8) 2진수(b)
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답: 10 1010
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답: IPv4는 각 자리마다 8비트로 이루어진 총 32비트로 구성되어있기 때문이다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답: 32비트는 2³²승으로 약 42억 9,496만 개 (43억 개)의 고유한 주소를 만들 수 있다.
        32비트를 8비트(1바이트)씩 4개의 옥텟(Octet)으로 나누어 사용하고, 8비트로 표현할 수 있는 숫자의 범위가 0부터 255까지(2⁸ = 256)이다.
- (다-2) 32비트로 만들 수 있는 주소의 개수: 2³²승으로 약 42억 9,496만 개 (43억 개)
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답: 2³², 
    1) 비트 한 자리에 들어갈 수 있는 값은 0과 1인 두개이다.
    2) IPv4 주소 체계에서 지정한 총 비트의 자리 수는 32자리이다.
    3) 2를 32번 곱하면 2³²승이 된다.
    4) 2³² == 약 42억 9,496만 개 (43억 개)
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답: 약 43억 개라는 수치는 전 세계 모든 기기에 고유한 주소(공인 IP)를 하나씩 나누어 주기에 턱없이 부족하다.
  사설 IP(Private IP)의 도입: "내부에서만 돌려쓰는 주소"
  NAT(네트워크 주소 변환)의 역할: "통역사이자 대표자", 사설 IP를 공인 IP로 바꾸어 주는 기술이 NAT이다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- (가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP:
      ipconfig = 192.168.100.68
      curl = 1.245.252.171
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답: 192.168.0.0 ~ 192.168.255.255 이 범위안에 들어간다.
        내 IPv4주소는 192.168.100.68이고, 앞에 192.168이 같기 때문에 사설 IP이다.
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답: curl로 본 주소는 1.245.252.171이다 2.2표에 해당하지 않기 때문에 공인 IP이다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답: 출발지 주소가 `172.20.5.6`인 경우에는 172.16.0.0 ~ 172.31.255.255이 사설 IP 범위에 포함되기 때문에 내부망 주소라고 분류해야한다. 하지만 출발지 주소가 `172.32.5.6`인 경우에는 위에 주소에 포함되지 않기 때문에 공인 IP이다.
- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답: NAT는 내부망의 사설 IP를 공인 IP로 변환하는 기술이다. 여러 내부 PC가 하나의 공인 IP를 공유할 수 있기 때문에 외부 서버 로그에는 변환된 공인 IP만 기록된다. 따라서 출발지 IP만으로는 내부망의 어느 PC가 접속했는지 특정할 수 없다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답: 
    - 정적 NAT는 내부 사설 IP와 공인 IP를 1대1로 고정하여 매핑한다. 항상 같은 공인 IP와 사설 IP가 연결되어 유지되고, 외부에서 내부 서버(예: 웹서버, 메일서버)로 직접 접근해야 할 때 주로 사용한다. 사설 IP 개수만큼 공인 IP가 필요해서 절약하는 효과가 없다.
    - 동적 NAT는 사설 IP를 미리 정의된 공인 IP 풀(Pool)에서 동적으로 할당하여 변환한다. 통신이 필요할 때 공인 IP 풀에서 사용 가능한 IP를 임시로 부여한다. 통신이 끝나면 공인 IP를 반납하여 다른 내부 기기가 쓸 수 있게 한다. 
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
  - 답: 사원 PC 여러 대가 인터넷을 사용할 때 동적 NAT를 사용하는 이유는 제한된 공인 IP 주소를 효율적으로 사용하기 위해서이다. 동적 NAT는 내부 PC가 인터넷에 접속할 때 공인 IP를 동적으로 할당하므로 시간에 따라 사설 IP와 공인 IP의 대응 관계가 달라질 수 있다. 따라서 외부 서버 로그의 공인 IP만으로는 PC를 특정하기 어렵고, 접속 시각과 NAT 장비의 주소 변환 기록을 함께 확인해야 한다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답: 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT를 사용하는 것이 적합하다. 정적 NAT는 공인 IP와 사설 IP를 고정적으로 연결하므로 외부 사용자가 동일한 공인 IP를 통해 내부 웹 서버에 지속적으로 접속할 수 있기 때문이다. 반면 동적 NAT는 공인 IP 할당이 변경될 수 있어 외부에서 특정 서버에 안정적으로 접속하는 용도로는 적합하지 않다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것: 정적 NAT와 동적 NAT의 뜻과 구분해서 사용하는 방법.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수:
      내 서브넷 마스크 : 255.255.0.0
      CIDR : /16
      주소 수 : 65,536
      쓸 수 있는 수 : 65,534
- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분:
      내 IPv4 주소 : 192.168.100.68
      망 부분 : 192.168
      장비 부분 : 100.68
- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답: 255.255.0.0
        11111111.11111111.00000000.00000000
        1인 비트: 망(네트워크) 부분 — 어느 네트워크에 속하는지 나타냄
        0인 비트: 장비(호스트) 부분 — 해당 네트워크의 어느 장치인지 나타냄
        그래서 11111111.11111111.00000000.00000000 여기에서
        앞에 16비트가 네트워크 부분이고 뒤에 16비트는 호스트 부분이다.
- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답: 일단 서브넷 마스크가 255.255.0.0이고 이를 2진수로 바꿨을 때
        11111111.11111111.00000000.00000000이다.
        이때 1이 8개인 마디가 두 개라 8x2 = 16이다. 그래서 /16
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답: 일단 서브넷 마스크가 255.255.0.0이고 이를 2진수로 바꿨을 때
        11111111.11111111.00000000.00000000이다.
        서브넷 마스크가 255.255.0.0이므로 앞의 16비트는 네트워크 부분이고 뒤의 16비트는 호스트 부분이다. 같은 망에 속한 PC들은 네트워크 부분이 같고, 각 PC를 구분해야 하므로 호스트 부분은 다르다. 즉, 같은 망이란 동일한 네트워크 주소를 사용하는 것을 의미한다.
- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답: 내 서브넷 마스크는 서브넷 마스크가 255.255.0.0이고 이를 2진수로 바꿨을 때
        11111111.11111111.00000000.00000000이다.
        그럼 1인 비트인 망 부분은 앞 두마디인 192.168이고 장치는 각각 10.25와 20.25이다.
        망 부분이 동일하고 장치 부분만 다르기 때문에 같은 망이다.
- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답: /24인 서브넷 마스크는 11111111.11111111.11111111.00000000인 255.255.255.0이다.
        그럼 앞 세 마디가 망 부분이고, 뒤에 한 마디가 장비 부분이다.
        이때 `192.168.10.25`는 192.168.10이 망 부분이 되고, 25가 장비 부분이다.
        그리고 `192.168.20.25`는 192.168.20이 망 부분이 되고, 25가 장비 부분이다.
        192.168.10과 192.168.20는 다르기 때문에 다른 망이라고 할 수 있다.
- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답: 서브넷 마스크에 따라 같은 망인지 다른 망인지 달라지기 때문이다. 같은 망이면 직접 통신을 시도하지만 다른 망이면 게이트웨이를 통해 통신해야 한다. 또한 방화벽은 IP 주소와 네트워크 범위를 기준으로 통신을 허용하거나 차단하기 때문에 서브넷 마스크를 잘못 설정하면 허용하지 않아야 할 장비까지 접근하거나 정상적인 통신이 차단될 수 있다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일(`warmup_3_2b.py`)의 내 주소/CIDR · 출력 세 줄:
    192.168.100.68/16

    255.255.0.0
    192.168.0.0
    192.168.255.255
- (나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지:
    255.255.0.0     > ① 마스크
    192.168.0.0     > ② 망 부분
    192.168.255.255 > ③ 브로드캐스트 주소
- (나-2) 내 주소에서 `0` · `255` 로 바뀐 마디: 3번째 마디, 4번째 마디
- (나-3) 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.
  - 답: IP주소가 192.168.100.68이고
        서브넷이 255.255.0.0이면
        11000000 10101000 01100100 01000100 == 192.168.100.68
        11111111 11111111 00000000 00000000 == 255.255.0.0 이고
    AND 11000000 10101000 00000000 00000000 AND연산을 하게되면 이렇게 되기 때문에
        == 192.168.0.0이 된다.
- (나-4) 왜 그 마디만 바뀌고 나머지 마디는 그대로인지 망 부분과 장비 부분으로 설명하세요.
  - 답: IP주소의 망 부분은 192.168이고, 장비 부분은 100.68이다.
        서브넷 마스크가 255.255.0.0이므로 AND 연산을 하면 1인 비트에 해당하는 망 부분은 그대로 유지되고, 0인 비트에 해당하는 장비 부분은 모두 0으로 바뀐다. 따라서 앞의 두 마디는 그대로이고 뒤의 두 마디만 0으로 변경된다.
- (다-1) `ipconfig` 의 내 기본 게이트웨이 주소가 둘째 줄과 셋째 줄 사이에 있는지(예 · 아니오): 예
- (다-2) 게이트웨이 주소가 이 범위 안에 있어야 하는 이유를 설명하세요.
  - 답: 기본 게이트웨이는 내 PC가 다른 네트워크와 통신할 때 거쳐 가는 장비이다. 
        따라서 내 PC가 게이트웨이에 직접 패킷을 전달할 수 있도록 같은 네트워크에 있어야 한다. 게이트웨이 주소가 같은 네트워크 범위에 있지 않으면 일반적인 설정에서는 게이트웨이에 도달하지 못해 외부 네트워크와 통신하기 어렵다.
- (다-3) 게이트웨이 주소를 둘째 줄의 네트워크 주소나 셋째 줄의 브로드캐스트 주소로 잘못 설정하면 왜 문제가 되는지, 두 주소의 역할을 들어 설명하세요.

  - 답: 같은 망의 다른 장비가 게이트웨이 IP의 MAC 주소가 자신이라고 거짓으로 응답하면, 내 PC의 ARP 캐시에 잘못된 MAC 주소가 저장된다. 그러면 다른 망으로 패킷을 보낼 때 프레임의 목적지 MAC이 실제 게이트웨이가 아닌 공격자의 MAC으로 설정되어 패킷이 엉뚱한 장비로 전달된다. 이로 인해 통신이 끊기거나 공격자가 패킷을 가로채거나 변조할 수 있다.

## 최종 설계서 — 7교시에 완성합니다

> 오늘 설계한 회사망을 정리합니다. 5.2 · 6.3 의 표와 위에서 적은 6-2 의 답을 다시 보며 씁니다.

### 1. 부서마다 망 · VLAN · 게이트웨이 — 5.2 · 6.1 · 6.3

- 세 부서의 망 · VLAN · 게이트웨이:
  개발팀	192.168.10.0/24	VLAN 10	192.168.10.1
  운영팀	192.168.20.0/24	VLAN 20	192.168.20.1
  보안팀	192.168.30.0/24	VLAN 30	192.168.30.1
- 부서마다 VLAN 하나에 서브넷 하나를 맞춘 이유를, 서로 다른 VLAN 에 같은 서브넷을 주었을 때 PC 와 스위치가 각각 어떻게 동작하는지와 견주어 설명하세요.
  - 답: 부서마다 VLAN 하나에 서브넷 하나를 맞추는 이유는 네트워크를 논리적으로 분리하고 각 부서의 통신 경로를 명확하게 하기 위해서이다.
  서로 다른 VLAN에 같은 서브넷을 설정하면 PC는 같은 망이라고 판단하여 ARP 요청으로 상대 장비의 MAC 주소를 찾으려고 한다. 하지만 스위치는 VLAN별로 브로드캐스트 범위를 분리하므로 다른 VLAN으로 ARP 요청을 전달하지 않는다. 따라서 상대 장비의 MAC 주소를 찾지 못해 통신에 문제가 발생할 수 있다.

### 2. 라우팅 경로 — 6-2

- 운영팀 PC `192.168.20.30` → 인터넷 `8.8.8.8` 이 지나는 장비와, 라우터가 그때 쓴 라우팅 표의 줄: 운영팀 PC → VLAN 20의 네트워크 → 회사 라우터(기본 게이트웨이) → 인터넷 쪽 라우터(기본 경로 0.0.0.0) → 8.8.8.8
- 라우터가 6-2 의 `192.168.30.5`(보안팀 PC)와 이 통신(`8.8.8.8`)에서 다음 홉을 다르게 고른 이유를, 라우팅 표에서 맞는 줄을 찾는 순서로 설명하세요.
  - 답: 보안팀 PC인 192.168.30.5라면 라우팅 표의 192.168.30.0/24에 포함되므로 VLAN 30으로 전달한다. 따라서 목적지 IP와 일치하는 라우팅 표의 경로에 따라 다음 홉이 달라진다.

### 3. 오늘 하루 정리

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유: 오늘 배운 것 가운데 가장 중요하다고 생각하는 것은 서브넷 마스크와 라우팅이다. 서브넷 마스크를 이용해 IP 주소의 네트워크 부분과 호스트 부분을 구분할 수 있고, 이를 통해 같은 망인지 다른 망인지 판단할 수 있다는 것을 알게 되었다. 또한 다른 망으로 패킷을 보낼 때는 라우터가 목적지 IP와 라우팅 표를 비교하여 전달 경로를 결정한다는 것을 배웠다.
