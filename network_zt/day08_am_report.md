        ③ `docker logs` 에 요청 줄이 있었는지 : Nginx 시작 메시지는 있었지만, 실제 접속 요청인 GET 기록은 없었다.
        ④ `compare-web-8085` 와 비교한 결과 : wrongport-web-8084는 8080 포트에 연결되어 000이 나왔고 GET 기록이 없었다. 반면 compare-web-8085는 컨테이너의 80 포트에 연결되어 200이 나왔으며 GET 기록도 확인되었다.

  - 쓸 내용: ① 유형 ② 근거 세 가지 이상 ③ `favicon.ico` 404 와의 차이
  - 답: ① 유형: 위협 의심(관리자 페이지 및 설정 파일 탐색 시도)

- (답장) 보안 담당에게 보낼 답장을 씁니다. A · B · C 마다 유형 · 확인한 근거 · 먼저 할 일을 적어 주세요.
  - 쓸 내용: A · B · C 마다 ① 유형 ② 확인한 근거(`PORTS` 값 · 응답 번호 · 기록 줄) ③ 먼저 할 일

  - 확인한 근거: `closed-web-8081`은 `127.0.0.1:8081->80/tcp`로 설정되어 내 PC의 IP 주소로 접속했을 때 000이 나왔다. 반면 `open-web-8082`는 `0.0.0.0:8082->80/tcp`로 열려 있었고, 내 PC의 IP 주소로 접속했을 때 200이 나왔다.
  - 먼저 할 일: 개발용 서버를 외부에서 접속할 필요가 없다면 `-p 127.0.0.1:8082:80`으로 제한하고, 필요한 경우에만 방화벽으로 허용할 출발지 IP를 지정한다.

  알림 B — 장애
  - 확인한 근거: `wrongport-web-8084`는 Up 상태였지만 `8084->8080/tcp`로 연결되어 000이 발생했고, Nginx의 GET 접속 기록도 없었다. 반면 `compare-web-8085`는 `8085->80/tcp`로 연결되어 200이 나왔고 GET 기록도 확인되었다.

  - 확인한 근거: 동일한 출처에서 짧은 시간 동안 `/admin`, `/login`, `/.env`, `/wp-login.php`, `/backup.zip`에 연속적으로 접근해 404가 다섯 번 발생했다. `/index.html`은 200으로 처리되어 웹 서버 자체는 정상적으로 응답했다.
  - 먼저 할 일: 요청 출처 IP와 시각, User-Agent를 확인하고 같은 형태의 반복 요청이 있는지 조사한다. 실제 공격 여부를 확인한 뒤 필요하면 해당 출처의 접근 제한이나 경로별 접근통제를 적용한다.

  - 쓸 내용: 자유롭게
  - 답: Docker 컨테이너가 Up 상태라고 해서 웹 서버가 정상적으로 응답하는 것은 아니라는 것을 새로 알게 되었다. 특히 외부 포트와 컨테이너 내부 포트를 잘못 연결하면 서버가 실행 중이어도 000이 발생할 수 있고, docker logs에서 실제 GET 요청이 남았는지 확인하면 원인을 좁힐 수 있다는 점이 기억에 남았다. 또한 같은 404라도 favicon.ico처럼 일반적인 파일 누락일 수 있고, 관리자 페이지나 설정 파일을 연속적으로 요청하는 경우에는 위협을 의심할 수 있으므로 출처와 시각, 경로를 함께 분석해야 한다는 것을 알게 되었다.

### 문제 3-1 · 거부 직후 허용 찾고 이유별 막대그래프 그리기

- (가) 내가 채운 코드를 붙여 넣어 주세요.
  - 쓸 내용: `# ←` 네 곳에 채운 코드(`json.loads` · 거부 후 허용 · `last` 기억 · 막대 출력 한 줄)
  - 답:

```
# 1. 임시 값입니다. text 를 json.loads 로 딕셔너리로 바꾼 값으로 바꾼다   # ←
line = json.loads(text)
# 2. user 가 last 에 있고, last[user][0] 이 "거부" 이고, line["decision"] 이 "허용" 이고, now - last[user][1] 이 10 이하이면 "[거부 후 허용]", user, line["time"], line["device"] 를 출력한다   # ←
    if user in last and last[user][0] == "거부"and line["decision"] =="허용" and now - last[user][1] <=10:
        print("[거부 후 허용]", user, line["time"], line["device"])
# 3. last[user] 에 (line["decision"], now) 를 기억한다   # ←
    last[user] = (line["decision"], now)
# 4. reason, "#" 를 count 만큼 반복한 글자, count 를 출력한다   # ←
    print(reason, "#"*count, count)
```

- (나) 🔍 「거부 후 허용」으로 나온 건 중 정상 재시도로 보이는 것과 의심스러운 것을 가르고, 근거(거부 이유 · 기기)를 적어 주세요.
  - 쓸 내용: 「정상 재시도: 계정 · 시각, 근거 / 의심: 계정 · 시각, 근거」
