## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:

```
def jitter(got):
    """
    받은 ping 응답 시간의 이웃한 값 차이로 지터를 계산한다.
    입력: 응답을 받은 시간 값들이 담긴 리스트 got
    리턴: 이웃한 응답 시간 차이의 절댓값 평균(ms)
    """
    total = 0

    for i in range(1, len(got)):
        total += abs(got[i] - got[i - 1])

    return total / (len(got) - 1)
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답:
      회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
      회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
      회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: ① `jitter` 함수는 응답을 받은 시간 리스트 `got`에서 이웃한 두 값의 차이의 절댓값을 구하고, 그 평균인 지터(ms)를 반환한다.

        ② `measure` 함수 안의 `jitter_value = jitter(got)` 줄에서 `got`을 전달하고, 반환된 지터를 `jitter_value` 변수에 저장하여 결과를 출력할 때 사용한다.

  - 답: `tracert`를 통해 목적지 서버까지 거치는 장비와 구간별 지연을 확인할 수 있다는 것을 새로 알게 되었다. 특히 중간 홉 하나의 응답 시간이 높더라도 뒤쪽 홉의 시간이 다시 낮아지면 실제 통신 장애가 아닐 수 있다는 점이 기억에 남았다. 또한 한 번의 측정만으로 장애 원인을 확정할 수 없으므로, ping과 tracert를 다른 시간대에도 반복 측정하고 사내 구간과 통신사 구간을 구분하여 확인하는 것이 중요하다는 것을 알게 되었다.

### 3. 지연 원인 — 문제 7-1 · 7-2

- SaaS 접속이 느린 원인 구간과 그 근거를 적어 주세요.
  - 쓸 내용: ① 원인 구간 ② 근거(tracert 에서 뛴 값) ③ 사내 구간이 정상이라는 근거
  - 답: SaaS 접속 지연이 증가한 것으로 의심되는 구간은 4번 홉과 5번 홉 사이이다.

        사내 공유기(1번 홉)는 1ms, 사내 방화벽(2번 홉)은 2ms로 큰 지연이 관찰되지 않았다. 반면 통신사 중계 장비인 4번 홉에서 해외 연결 지점인 5번 홉으로 넘어가면서 지연이 6ms에서 48ms로 약 42ms 증가했다.

        또한 ping 결과 평균 지연은 평소 22ms에서 52ms로 증가했지만 지터는 2ms, 손실률은 0%였다.

        따라서 사내 구간보다는 통신사 중계 장비와 해외 연결 지점 사이의 외부 구간에서 지연이 증가한 것으로 의심된다
