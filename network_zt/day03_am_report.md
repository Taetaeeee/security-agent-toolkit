## 2교시 · nslookup

### 문제 2-1 · 도메인 이름을 IP 주소로 — 두 DNS 서버에 묻기

- (가-1) 처음 `nslookup example.com` 을 쳤을 때, 내가 물어본 DNS 서버의 주소와 example.com 의 IPv4 주소를 적어 주세요.
  - 쓸 내용: 화면 맨 위 `Address` 줄의 주소 하나, 아래쪽 `Addresses` 에서 숫자 네 개를 점으로 이은 주소 하나 — 두 개를 「서버: … / example.com: …」처럼. 맥북은 맨 위 `Address`, 아래 `Name:` 다음 `Address` 줄
  - 답: 서버:    kns.kornet.net
        Address:  168.126.63.1

        이름:    example.com
        Addresses:   172.66.147.243
                     104.20.23.154
- (가-2) `nslookup example.com 8.8.8.8` 을 쳤을 때, 맨 위 `서버` 줄에 나온 이름과 example.com 의 IPv4 주소를 적어 주세요.
  - 쓸 내용: `서버` 줄의 이름 하나(맥북은 `Server`), IPv4 주소 하나. 시간 초과가 났으면 「시간 초과」라고 적어도 됩니다
  - 답: 서버:    dns.google
        Address:  8.8.8.8

        이름:    example.com
        Addresses:   104.20.23.154
                     172.66.147.243
- (나) 🔍 화면 위쪽 `Address` 와 아래쪽 `Addresses` 는 각각 무엇의 주소일까요? 두 화면을 비교해서 적어 주세요.
  - 쓸 내용: ① 두 화면에서 바뀐 쪽과 그대로인 쪽 ② 그렇게 된 이유 — 위쪽 · 아래쪽이 각각 무엇의 주소인지를 근거로 쓰기
  - 답: 위쪽 Address는 DNS 조회에 사용한 DNS 서버의 IP 주소이고, 아래쪽 Addresses는 DNS 서버가 응답한 example.com의 IP 주소이다. 두 화면에서 위쪽 DNS 서버 주소는 168.126.63.1에서 8.8.8.8로 바뀌었지만, 아래쪽 example.com의 IPv4 주소는 순서만 다르고 동일하다. 이는 DNS 서버가 달라도 같은 도메인에 대한 IP 주소를 응답할 수 있기 때문이다.
- (다-1) 회사 PC 가 회사 DNS 서버 대신 `8.8.8.8` 같은 외부 DNS 서버에 직접 묻고 있다면, 관제 담당자는 왜 이것을 확인해야 할까요?
  - 쓸 내용: ① 회사 DNS 서버가 평소에 하는 일(검색해서 찾아도 됩니다) ② 외부 DNS 에 직접 물으면 그 일을 거치지 않게 되는 까닭
  - 답: 회사 DNS 서버는 도메인 이름을 IP 주소로 변환하고, 회사 정책에 따라 악성 사이트 차단이나 DNS 조회 기록을 관리할 수 있다. 하지만 회사 PC가 8.8.8.8과 같은 외부 DNS 서버에 직접 요청하면 회사 DNS 서버를 거치지 않으므로 이러한 보안 정책이나 로그 수집을 우회할 수 있다. 따라서 관제 담당자는 외부 DNS 사용이 정상적인 설정인지 확인해야 한다.
- (다-2) 내 PC 의 DNS 서버 설정이 나도 모르게 낯선 주소로 바뀌어 있다면, 어떤 일이 생길 수 있을까요?
  - 쓸 내용: ① 그 낯선 DNS 서버가 내 질문에 어떤 답을 줄 수 있는지 ② 그 답 때문에 내가 어디로 접속하게 되는지
  - 답: 내 PC의 DNS 서버가 나도 모르게 낯선 주소로 변경되면 악성 DNS 서버가 정상적인 도메인에 대해 잘못된 IP 주소를 알려줄 수 있다. 그러면 사용자는 정상적인 사이트 주소를 입력하더라도 공격자가 운영하는 가짜 사이트로 연결을 시도하게 되고, 피싱이나 개인정보 유출 등의 피해가 발생할 수 있다.

### 문제 2-2 · URL 에서 이름을 꺼내 묻기 — 없는 이름이면

- (가-1) `day03_2-2_url_example.py` 를 실행했을 때 나온 두 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널에 나온 출력 두 줄을 복사해 붙여 넣기
  - 답: ['https:', '', 'example.com', 'news', 'today']
        example.com → 172.66.147.243
- (가-2) `day03_2-2_url_nowhere.py` 의 맨 마지막 줄에 나온 에러 이름과, 같은 이름을 `nslookup` 했을 때 나온 문구를 적어 주세요.
  - 쓸 내용: 에러 이름은 마지막 줄의 `:` 앞부분 하나, `nslookup` 문구는 `Non-existent domain` 이 든 줄 하나(맥북은 `NXDOMAIN` 이 든 줄)
  - 답: socket.gaierror: [Errno 11001] getaddrinfo failed

        nslookup abc.nowhere-not-exist.com
        서버:    kns.kornet.net
        Address:  168.126.63.1

        *** kns.kornet.net이(가) abc.nowhere-not-exist.com을(를) 찾을 수 없습니다. Non-existent domain
- (나-1) `parts[2]` 를 꺼냈더니 도메인 이름이 나왔습니다. 왜 번호 2 칸에 도메인 이름이 있을까요?
  - 쓸 내용: ① (가-1) 첫 줄의 리스트를 0 번부터 세어 각 칸에 무엇이 있는지 ② `//` 사이에 무엇이 생겼는지
  - 답: day03_2-2_url_example.py의 URL을 /로 나누면 ['https:', '', 'example.com', 'news', 'today']가 된다. 인덱스는 0부터 시작하므로 parts[0]은 https:, parts[1]은 // 사이에 생긴 빈 문자열이고, parts[2]가 example.com이 된다. 따라서 2번 인덱스에서 도메인 이름을 가져올 수 있다.
- (나-2) 두 번째 파일은 왜 마지막 줄에서 에러가 나며 멈췄을까요? `nslookup` 결과와 이어서 적어 주세요.
  - 쓸 내용: ① `gethostbyname()` 이 DNS 서버에 무엇을 물었는지 ② DNS 서버가 어떤 답을 했는지 ③ 그래서 왜 에러가 났는지
  - 답: gethostbyname()은 DNS를 이용해 abc.nowhere-not-exist.com의 IPv4 주소를 조회하려고 했다. 하지만 DNS 서버가 해당 도메인을 찾을 수 없다는 NXDOMAIN 응답을 반환했기 때문에 IPv4 주소를 얻지 못했고, 그 결과 socket.gaierror가 발생하여 프로그램이 중단되었다.
- (다) 🔍 `Non-existent domain`(NXDOMAIN) 이 나왔다고 인터넷이 끊긴 걸까요? 아니라면 왜 아닌지 적어 주세요.
  - 쓸 내용: ① DNS 서버가 답을 했는지 안 했는지 ② 인터넷이 정말 끊겼다면 화면이 어떻게 달랐을지
  - 답: NXDOMAIN이 나왔다고 인터넷이 끊긴 것은 아니다. DNS 서버가 요청을 받고 해당 도메인이 존재하지 않는다는 응답을 보낸 것이기 때문이다. 반면 인터넷 연결이 끊겨 DNS 서버에 접근하지 못했다면 NXDOMAIN 대신 요청 시간 초과나 DNS 서버 응답 실패 등의 메시지가 나타날 수 있다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요. (「이 교시에 새로 안 것」 칸)
  - 쓸 내용: 새로 안 것 하나와, 그게 왜 기억에 남는지
  - 답: DNS 서버가 도메인 이름을 찾지 못하면 NXDOMAIN이라는 응답을 보낸다는 것을 알게 되었다. 처음에는 오류가 발생하면 인터넷 연결에 문제가 있는 것으로 생각했지만, DNS 서버가 응답했더라도 해당 도메인이 존재하지 않아 오류가 발생할 수 있다는 점이 기억에 남았다.

## 3교시 · DNS 계층

### 문제 3-1 · 레이블로 나누고 권한 있는 네임서버 찾기

- (가-1) `day03_3-1_labels_kr.py`(`mail.google.co.kr`)를 실행했을 때 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답: kr
        co.kr
        ['kr', 'co', 'google', 'mail']
- (가-2) `nslookup -type=ns example.com` 에서 `nameserver =` 뒤에 나온 이름을 모두 적고, 몇 개였는지도 적어 주세요.
  - 쓸 내용: 네임서버 이름들과 개수. `internet address` 줄의 IP 는 적지 않습니다
  - 답: 2개
      example.com     nameserver = elliott.ns.cloudflare.com
      example.com     nameserver = hera.ns.cloudflare.com
- (나) 두 번째 파일의 둘째 줄은 `google.co.kr` 이 아니라 `co.kr` 로 나왔습니다. 왜 그럴까요?
  - 쓸 내용: ① `[-2:]` 가 몇 개의 레이블을 꺼내는지 ② `.kr` 아래에 어떤 계층이 하나 더 있는지(안내 3.1 절 참고)
  - 답: mail.google.co.kr을 .으로 나누면 ['mail', 'google', 'co', 'kr']이 된다. [-2:]는 마지막 두 개의 레이블을 가져오므로 co와 kr을 선택한다. 또한 .kr 아래에는 .co.kr이라는 계층이 하나 더 있기 때문에 google.co.kr이 아니라 co.kr이 출력된다.
- (다-1) (가-2) 에서 본 것처럼 한 도메인에 네임서버를 둘 이상 두는 이유는 무엇일까요?
  - 쓸 내용: 네임서버가 하나뿐일 때 그 서버가 멈추면 무슨 일이 생기는지
  - 답: 한 도메인에 네임서버를 둘 이상 두는 이유는 장애가 발생해도 DNS 서비스를 유지하기 위해서이다. 네임서버가 하나뿐이면 해당 서버가 멈췄을 때 도메인의 IP 주소를 조회하지 못할 수 있지만, 여러 개가 있으면 하나가 멈추더라도 다른 네임서버가 응답할 수 있다.
- (다-2) 어떤 회사 도메인의 네임서버가 갑자기 낯선 서버로 바뀌었다면, 어떤 일이 생길 수 있을까요?
  - 쓸 내용: ① 권한 있는 네임서버가 그 도메인에 대해 정하는 것 ② 그 서버를 공격자가 관리하게 되면 웹 · 메일 접속이 어떻게 되는지
  - 답: 권한 있는 네임서버는 해당 도메인의 IP 주소와 메일 서버 등의 DNS 정보를 제공한다. 만약 회사 도메인의 네임서버가 공격자가 관리하는 서버로 변경되면 공격자가 잘못된 IP 주소나 메일 서버 정보를 응답할 수 있다. 그 결과 사용자가 정상적인 회사 주소를 입력해도 가짜 웹 사이트로 연결되거나 회사로 보내는 메일이 공격자 서버로 전달될 수 있다.

### 문제 3-2 · 권한 있는 네임서버에게 직접 묻기

- (가-1) `nslookup example.com`(리졸버에 물은 화면)에 `권한 없는 응답:` 줄이 있었는지, 그리고 IPv4 주소를 적어 주세요.
  - 쓸 내용: 「있음 / 없음」 하나와 IPv4 주소 하나. 맥북은 `Non-authoritative answer:` 줄
  - 답: 있음. Addresses:  104.20.23.154
                         172.66.147.243
- (가-2) 권한 있는 네임서버에 직접 물은 화면에 `권한 없는 응답:` 줄이 있었는지, 그리고 IPv4 주소를 적어 주세요.
  - 쓸 내용: 「있음 / 없음」 하나와 IPv4 주소 하나(맥북은 `Non-authoritative answer:` 줄). 시간 초과면 「시간 초과」라고 적어도 됩니다
  - 답: 없음. Addresses:  104.20.23.154
                         172.66.147.243
- (나-1) 🔍 두 화면에서 `권한 없는 응답:` 줄이 한쪽에만 나온 이유는 무엇일까요?
  - 쓸 내용: ① 첫 화면은 누가 답했는지 ② 둘째 화면은 누가 답했는지 ③ 그 차이가 왜 그 줄로 나타나는지
  - 답: 1) DNS 리졸버 2) 권한 있는 네임서버
    3) 첫 번째 화면은 DNS 리졸버가 다른 DNS 서버에서 가져오거나 캐시에 저장한 정보를 이용해 응답했기 때문에 '권한 없는 응답'이 표시되었다. 반면 두 번째 화면은 example.com의 권한 있는 네임서버가 직접 응답했기 때문에 '권한 없는 응답'이 표시되지 않았다.
- (나-2) 「권한 없는 응답」이라는 이름 때문에 틀린 답처럼 들립니다. 정말 틀린 답일까요?
  - 쓸 내용: ① 리졸버가 그 답을 어디서 받아 왔는지 ② (가-1) · (가-2) 의 IPv4 가 같았는지
  - 답: 권한 없는 응답이라고 해서 틀린 답이라는 뜻은 아니다. 리졸버는 권한 있는 네임서버 등을 통해 얻은 정보를 캐시에 저장하거나 조회하여 응답할 수 있다. 실제로 (가-1)과 (가-2)에서 나온 IPv4 주소가 동일하므로 이번 조회에서는 리졸버도 같은 정보를 제공했다는 것을 알 수 있다.
- (다) 리졸버가 준 답이 이상해 보일 때, 권한 있는 네임서버에 직접 물어보면 무엇을 알 수 있을까요?
  - 쓸 내용: 두 답이 같을 때와 다를 때 각각 무엇을 알 수 있는지
  - 답: 리졸버의 응답이 이상해 보일 때 권한 있는 네임서버에 직접 물어보면 두 응답을 비교할 수 있다. 두 응답이 같다면 리졸버가 권한 있는 네임서버와 동일한 IP 주소를 제공했다는 것을 알 수 있다. 반면 응답이 다르다면 오래된 DNS 캐시나 DNS 설정 변경, 응답 변조 등의 가능성을 확인할 수 있다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요. (「이 교시에 새로 안 것」 칸)
  - 쓸 내용: 새로 안 것 하나와, 그게 왜 기억에 남는지
  - 답: 권한 없는 응답이라고 해서 잘못된 정보라는 뜻이 아니라는 것을 새로 알게 되었다. DNS 리졸버는 권한 있는 네임서버에서 얻었거나 캐시에 저장된 정보를 이용해 응답할 수 있으며, 실제로 두 서버에서 조회한 IPv4 주소가 같았다. 처음에는 '권한 없는 응답'이라는 문구가 오류처럼 느껴졌지만, 응답한 서버의 역할을 구분하는 표현이라는 점이 기억에 남았다.

## 4교시 · 레코드와 캐시

### 문제 4-1 · 메일 서버와 별칭 — MX · CNAME

- (가-1) `nslookup -type=mx google.com` 에서 메일 서버 이름(`mail exchanger =` 뒤)과 우선순위 숫자(`MX preference`)를 적어 주세요.
  - 쓸 내용: 메일 서버 이름 하나, 숫자 하나. 아래에 같이 나오는 IP 는 적지 않습니다
  - 답: mail exchanger = smtp.google.com, MX preference = 10
- (가-2) `nslookup www.naver.com` 에서 `Aliases:` 줄의 이름과 `이름:` 줄의 최종 이름을 적어 주세요.
  - 쓸 내용: `Aliases:` 에 나온 이름, `이름:` 에 나온 이름. 맥북은 `canonical name =` 뒤가 최종 이름입니다
  - 답: Aliases:  www.naver.com, 이름:    www.naver.com.nheos.com
- (나-1) MX 레코드는 왜 IP 가 아니라 서버 이름으로 답할까요? 그 서버의 IP 는 어떻게 알아낼까요?
  - 쓸 내용: ① 서버 이름으로 적어 두면 좋은 점(서버 IP 가 바뀌는 경우를 생각해 보세요) ② IP 를 알아내는 방법(안내 4.1 절의 표 참고)
  - 답: MX 레코드는 메일 서버의 IP 주소가 변경되더라도 서버 이름을 유지하면서 관리할 수 있기 때문에 IP 주소 대신 서버 이름을 사용한다. 해당 서버의 IPv4 주소는 A 레코드로 조회할 수 있으며, IPv6 주소는 AAAA 레코드로 조회할 수 있다.
- (나-2) `www.naver.com` 은 왜 다른 이름(정식 이름)을 가리키고 있을까요?
  - 쓸 내용: ① CDN 이 무엇인지 한 줄 ② 큰 사이트가 CNAME 으로 CDN 이름을 가리키게 하는 까닭
  - 답: CDN은 콘텐츠를 여러 지역의 서버에 저장하여 사용자와 가까운 서버에서 빠르게 제공하는 서비스이다. 큰 사이트에서는 CNAME을 사용해 도메인을 CDN이 관리하는 이름으로 연결할 수 있다. 이렇게 하면 사용자가 입력하는 주소를 변경하지 않고도 실제 연결되는 서버를 관리하거나 변경할 수 있다.
- (다) 🔍 의심스러운 메일을 받았을 때, 보낸 쪽 도메인의 MX 레코드를 확인하면 무엇을 알 수 있을까요?
  - 쓸 내용: ① 정상 회사 도메인의 MX 는 보통 어떤지 ② MX 가 없거나 낯설면 무엇을 의심할 수 있는지
  - 답: 정상적인 회사 도메인의 MX 레코드는 보통 회사가 사용하는 메일 서버나 메일 서비스의 서버를 가리킨다. 의심스러운 메일을 받았을 때 해당 도메인의 MX 레코드를 확인하면 어떤 서버가 메일을 수신하도록 설정되어 있는지 알 수 있다. MX 레코드가 없거나 낯선 서버로 변경되어 있다면 메일 설정 오류나 도메인 악용 가능성을 의심할 수 있다. 다만 MX 레코드만으로 메일의 진위를 판단할 수는 없다.

### 문제 4-2 · 내 PC 의 DNS 캐시와 TTL

- (가-1) `ipconfig //displaydns` 에서 본 `example.com` 의 TTL 숫자와, `//flushdns` 뒤에 그 항목이 남아 있었는지 적어 주세요.
  - 쓸 내용: 숫자 하나와 「남음 / 없어짐」 하나. 맥북은 「건너뜀」, 「표시할 수 없습니다」가 나오면 옆 사람 화면의 값
  - 답: 149 없어짐
- (가-2) `day03_4-2_ttl_60.py`(`ttl = 60`)를 실행했을 때 나온 네 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 네 줄을 복사해 붙여 넣기
  - 답: 30 초: 캐시의 답을 쓴다
        100 초: DNS 서버에 새로 묻는다
        299 초: DNS 서버에 새로 묻는다
        300 초: DNS 서버에 새로 묻는다
- (나) 첫 파일과 두 번째 파일에서 100초 줄의 결과가 다릅니다. 왜 그럴까요?
  - 쓸 내용: ① 두 파일의 만료 시각(저장한 시각 + TTL)을 각각 계산 ② 100 이 각 만료 시각보다 작은지 큰지
  - 답: 첫 번째 파일은 저장 시각이 0초이고 TTL이 300초이므로 만료 시각은 300초이다. 두 번째 파일은 저장 시각이 0초이고 TTL이 60초이므로 만료 시각은 60초이다. 따라서 현재 시간이 100초일 때 첫 번째 파일은 만료 시각인 300초보다 작아 캐시의 답을 사용하지만, 두 번째 파일은 만료 시각인 60초를 지났기 때문에 DNS 서버에 새로 묻는다.
- (다-1) 🔍 사이트가 서버 IP 를 바꿨는데도, 한동안은 옛 IP 로 접속되는 사람이 있습니다. 왜 그럴까요?
  - 쓸 내용: ① 캐시에 무엇이 저장되는지 ② TTL 이 지나기 전에는 어떻게 동작하는지
  - 답: DNS 캐시에는 도메인 이름과 해당 IP 주소 등의 응답 정보가 저장된다. 사이트의 서버 IP가 변경되더라도 기존 IP 주소가 캐시에 남아 있고 TTL이 지나지 않았다면 DNS 서버에 새로 묻지 않고 저장된 IP를 사용하기 때문에 한동안 옛 IP로 접속될 수 있다.
- (다-2) 어떤 PC 가 계속 이상한 주소로 접속된다면, 관제 담당자는 왜 `ipconfig //flushdns` 부터 해 볼까요?
  - 쓸 내용: ① 캐시에 어떤 답이 남아 있을 수 있는지 ② 비운 뒤에는 PC 가 어떻게 다시 묻는지
  - 답: PC의 DNS 캐시에 오래되거나 잘못된 IP 주소가 남아 있으면 정상적인 사이트가 아닌 다른 주소로 접속될 수 있다. 따라서 관제 담당자는 ipconfig /flushdns를 사용해 DNS 캐시를 삭제한다. 이후 PC가 해당 도메인을 다시 조회하면 설정된 DNS 서버에 새로 요청하여 IP 주소를 받아올 수 있다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요. (「이 교시에 새로 안 것」 칸)
  - 쓸 내용: 새로 안 것 하나와, 그게 왜 기억에 남는지
  - 답: DNS 캐시는 도메인 이름과 IP 주소 등의 정보를 임시로 저장하고, TTL에 따라 저장된 정보를 사용할 수 있는 시간이 정해진다는 것을 새로 알게 되었다. 특히 서버의 IP 주소가 변경되더라도 TTL이 지나지 않았다면 기존 IP 주소로 접속할 수 있다는 점이 기억에 남았다. 또한 `ipconfig /flushdns` 명령어로 PC에 저장된 DNS 캐시를 삭제할 수 있다는 것도 알게 되었다.
