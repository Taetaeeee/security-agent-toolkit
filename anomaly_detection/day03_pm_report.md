  - 쓸 내용: ① 출력 전체(첫 번째 코드 상자에 붙여 넣기) ② `alerts.json` 내용(두 번째 코드 상자에 붙여 넣기) ③ 알림 건수
  - 답: ③ 알림 건수 2건

```

--- 단계 2: 트래픽 급증 알림 1 건

--- 단계 4: 저장된 알림
```

- (나) 🔍 ① 203.0.113.50 이 `normalized_events.json` 의 `source` 가 `web` 인 줄에 몇 시에 나오는지 찾고, ② 그 시각이 급증 알림의 분(09:12)과 같은지 비교하고, ③ 두 알림이 같은 일과 관련이 있는지 적고, 담당자가 두 건을 한 건으로 합쳐 조사할지 따로 조사할지 고른 이유를 적어 주세요.
  - 쓸 내용: ① 203.0.113.50 이 나오는 시각 ② 09:12 와 같은지 ③ 같은 일인지와 담당자가 두 건을 다루는 방법
  - 답: ① 203.0.113.50 이 나오는 시각 : 2026-11-02 09:12:01, 09:12:03, 09:12:06, 09:12:09, 09:12:12, 09:12:15, 09:12:18, 09:12:25, 09:12:27 총 9번의 요청이 발생했다.
  ② 09:12 와 같은지 : 모두 09:12에 발생한 요청이므로 급증 알림이 발생한 시간과 같다.
  ③ 같은 일인지와 담당자가 두 건을 다루는 방법 : 203.0.113.50에서 로그인 요청이 5번 실패하여 비정상 로그인 알림이 발생했고, 같은 IP에서 1분 동안 총 9번의 요청이 발생하여 트래픽 급증 알림도 발생했기 때문이다. 따라서 두 알림을 하나의 사건으로 연결해서 조사하는 것이 좋다고 생각한다. 다만 로그인 실패와 트래픽 급증은 서로 다른 규칙으로 발생한 알림이므로, 알림 기록은 각각 남겨 두고 조사 결과를 함께 정리해야 한다.

- (다) 🔍 203.0.113.50 알림을 조사해 보니 직원이 비밀번호를 잊어 반복해서 입력한 것이었습니다. ① `status` 를 어떤 값으로 바꿀지(안내 문서 6.1 의 처리 상태 순서를 참고), ② `note` 에 무엇을 더 적을지, ③ 알림을 지우지 않고 남겨 두는 편이 좋은 이유를 적어 주세요. 코드는 고치지 않고 글로만 적습니다.
  - 쓸 내용: ① 바꿀 `status` 이름 ② `note` 에 더 적을 내용 ③ 알림을 남겨 두는 이유
  - 답: ① 바꿀 `status` 이름 : 조사 완료
  ② `note` 에 더 적을 내용 : 조사 결과, 담당 직원이 비밀번호를 잊어 로그인에 반복해서 실패한 것으로 확인되었다. 비정상적인 공격이 아닌 정상 사용자의 입력 실수로 판단하였다.
  ③ 알림을 남겨 두는 이유 : 나중에 비슷한 알림이 발생했을 때 이전 조사 결과와 비교하기 위해서이다. 또한 해당 알림을 누가 어떤 이유로 정상적인 요청이라고 판단했는지 기록을 남겨 두면 같은 문제를 반복해서 조사하는 일을 줄일 수 있다. 이러한 기록은 불필요한 알림이 발생하는 원인을 확인하고, 이후 알림 기준을 개선할 때도 활용할 수 있다.
